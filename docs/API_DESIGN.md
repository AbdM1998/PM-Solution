# API Design — ProjectFlow

Base URL: `http://localhost:4000/api`. JSON over HTTPS in production, HTTP locally.
Auth: `Authorization: Bearer <accessToken>` (JWT, 15 min) + refresh via httpOnly cookie
(`/auth/refresh`). All list endpoints are paginated (`?page=&pageSize=`, default 20,
max 100) and return `{ items, total, page, pageSize }`. All timestamps are UTC ISO
8601 on the wire; clients convert using the user's `timezone`.

Full OpenAPI is generated by the backend at `/api/docs` (Swagger UI) — this file is the
human-readable contract the web/mobile/worker teams build against before that exists.

## Auth
- `POST /auth/register` — email, password, name → user + tokens
- `POST /auth/login` — email, password → tokens
- `POST /auth/refresh` — rotate access token from refresh cookie
- `POST /auth/logout`
- `GET /auth/me`

## Projects
- `GET /projects` — filters: status, priority, tag, search, sort
- `POST /projects`
- `GET /projects/:id` — includes computed fields: `durationDays`, `daysElapsed`,
  `daysRemaining`, `daysOverdue`, `completionPercent`, `completedTaskCount`,
  `pendingTaskCount`, `overdueTaskCount` (all **computed server-side from real task/
  checklist state**, never a stored/editable percent field)
- `PATCH /projects/:id`
- `DELETE /projects/:id` (soft rules: blocked if it has tasks unless `?force=true`)
- `GET /projects/:id/activity`

## Tasks
- `GET /projects/:projectId/tasks` — filters: status, priority, assignee, tag, search
- `POST /projects/:projectId/tasks`
- `GET /tasks/:id`
- `PATCH /tasks/:id`
- `DELETE /tasks/:id`
- `POST /tasks/:id/duplicate`
- `POST /tasks/reorder` — `{ taskId, newIndex }[]` for drag-and-drop
- `POST /tasks/bulk-complete` — `{ taskIds: string[] }`

## Checklist items
- `GET /tasks/:taskId/checklist-items`
- `POST /tasks/:taskId/checklist-items`
- `PATCH /checklist-items/:id` (title, due date, priority, notes, parentId for nesting)
- `POST /checklist-items/:id/complete` → cancels its pending `ReminderOccurrence`s
  (see `docs/REMINDER_ENGINE.md`)
- `DELETE /checklist-items/:id`
- `POST /checklist-items/reorder`
- `POST /checklist-items/bulk-complete`

## Checklist templates
- `GET /checklist-templates`
- `POST /checklist-templates` — `{ name, items: [{ title, defaultPriority, orderIndex }] }`
- `POST /checklist-templates/:id/apply` — `{ taskId }` → creates all items on the task

## Reminders
- `GET /reminders?entityType=&entityId=`
- `POST /reminders` — `{ entityType, entityId, type, scheduledAt?, recurrenceRule?,
  offsetBeforeDueMinutes?, channels }`
- `PATCH /reminders/:id`
- `DELETE /reminders/:id` → cancels its future occurrences
- `GET /reminders/occurrences?status=&from=&to=` — used by Calendar + Dashboard
- `POST /occurrences/:id/complete`
- `POST /occurrences/:id/snooze` — `{ option: "5m"|"10m"|"30m"|"1h"|"later_today"|
  "tomorrow"|"next_week"|"custom", customAt? }`

## Dashboard / My Day
- `GET /dashboard/summary` — totals (projects by status, tasks due today, overdue,
  upcoming reminders, pending checklists, recently updated projects, recent activity)
- `GET /dashboard/my-day` — `{ today: [...], overdue: [...], completedToday: [...],
  snoozed: [...] }` merged across every project, sorted by effective time

## Tags
- `GET /tags`, `POST /tags`, `PATCH /tags/:id`, `DELETE /tags/:id`

## Email & Threads
- `GET /projects/:projectId/email-threads`
- `POST /projects/:projectId/email-threads` — manual linking (subject, conversationId,
  externalUrl, notes)
- `POST /projects/:projectId/email-threads/import` — multipart upload of `.eml`/`.msg`,
  parsed server-side (`mailparser` / `@kenjiuno/msgreader`), HTML sanitized before
  storage (`sanitize-html`)
- `GET /email-threads/:id/messages`
- `GET /email-connections` / `POST /email-connections/outlook/connect` /
  `POST /email-connections/gmail/connect` — OAuth adapter endpoints; return
  `501 Not Configured` with a clear message until real app-registration credentials
  are present in `.env` (see `docs/FINAL_DELIVERY_REPORT.md`)

## Notifications
- `GET /notifications?unread=true`
- `POST /notifications/:id/read`
- `POST /notifications/read-all`
- WebSocket (`Socket.io`, namespace `/notifications`) pushes `notification:new` events
  in real time for IN_APP channel deliveries.

## Device registration (mobile/web push)
- `POST /devices/register` — `{ platform, token }`
- `POST /push-subscriptions` — browser Web Push subscription object

## Health & ops
- `GET /health` — DB connectivity + worker heartbeat age
- `GET /health/ready`
